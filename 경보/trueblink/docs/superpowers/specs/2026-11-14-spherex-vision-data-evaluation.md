# SPHEREx Vision 데이터·학습·평가 계획

작성일: 2026-11-14 · 상태: 검증 전 계획. [설계서](2026-11-14-spherex-vision-design.md)의 R1–R8을 검증한다. 이 문서의 표본 수·허용오차·성능값은 **사전 기준**이며 측정된 결과가 아니다.

## 1. 세 가지 서로 다른 자료 집합

| 집합 | 용도 | 성공을 뜻하지 않는 것 |
|---|---|---|
| 고정 실제 노출 fixture | FITS/WCS/파장/PSF/단위 계약과 회귀 검증 | 천체 탐색 완전도 |
| 실제 영역의 blind injection | 알려진 진실값의 회수율·편향·오탐 비교 | 실제 우주의 모든 천체에 대한 성능 |
| 실제 후보의 검토 표본 | 아티팩트·혼잡·도메인 차이, 검색 관련성 | 카탈로그에 없는 모든 후보가 가짜라는 결론 |

세 결과를 분리해서 보고한다. 파일 하나에서 만든 여러 patch는 독립 관측 수로 세지 않는다.

## 2. P0 자료 확보와 수치 계약

기존 `tests/fixtures/golden_l2.json`, `golden_cube.json`, `targets.json`는 자료 발견 및 비교용이다. 작성 당시 파일의 존재와 메타데이터를 읽었다. 구현 때 출처·배열·보정 버전을 확인하고, 과학 기준값은 독립 Astropy 계산과 실제 byte range로 다시 만든다. 기존 fixture를 정답으로 그대로 복사해 자체 검증하지 않는다.

최소 fixture 구성:

- 각 검출기 1–6의 실제 노출, 검출기 중앙과 가장자리, 서로 다른 처리 layout 최소 2개.
- 압축/비압축 FLAGS의 읽기, NaN·mask·잘못된 헤더·분산 결측 사례.
- 동일 하늘 위치의 서로 다른 방문·파장 노출. full CWAVE/CBAND와 ePSF 자료를 각각 연결.
- cube와 L2를 구분하고 ZODI를 정확히 한 번 적용하는 예제.
- RA 0/360 경계·고위도, 원 검출기 x0/y0, 픽셀 중심·상하 방향, 부분 잘림 사례.

제안 수치 계약:

| 검사 | 통과 기준 | 해석 |
|---|---|---|
| 배열 해독 | 고정 byte-range와 bitwise 동일, NaN 위치 동일 | 손실 없는 전송·읽기 |
| WCS | 신뢰된 Astropy와 동일 좌표에서 차이 < 0.001 native pixel | 구현 오차 기준, 실제 천체 절대 위치 정확도 아님 |
| 단위 | MJy/sr↔µJy 픽셀 적분과 µJy↔mJy 상대오차 < 10⁻⁵ | Ω(pixel) 변화를 포함 |
| 파장 | 같은 full 보정 파일에 대한 독립 평가와 상대오차 < 10⁻⁵ | 파장 보정 자체의 물리적 정확도 아님 |
| ePSF | 정규화·원점·서브픽셀 이동·면적 적용을 알려진 주입으로 회수 | 보정 파일의 정의를 따른다. 잘린 stamp의 합을 무조건 1로 강제하지 않음 |
| JSON 계약 | NaN/Infinity 금지, 필수 상태/단위 존재, Python/TS 동일 fixture 통과 | 브라우저/분석 불일치 차단 |

독립 계산과 일치하지 않으면 원인을 밝히기 전 해당 분기를 과학 측정으로 사용하지 않는다.

## 3. 실제 하늘 표본

먼저 Barnard's Star, Epsilon Indi B, WISE 0855, RW Aur, R Dra 주변에서 자료 접근과 근거 화면을 확인한다. 이 다섯 대상은 서로 다른 현상을 살펴보는 사례이며 통계적 test set이 아니다. 희미한 대상의 실제 검출이나 모든 파장/시점의 관측 가능성을 미리 보장하지 않는다.

탐색 pilot은 12개 분리된 영역을 다음 층에서 2개씩 선택한다: 낮은 배경·희소, 높은 배경, 혼잡, 밝은 별 주변, 깊은 관측, 노출 수가 적은 경계. 이 결과는 버그·표본 설계에 사용하며 최종 성능 수치로 재사용하지 않는다.

모델 승격 평가에서는 train/validation/test를 각각 최소 30개 분리 영역으로 시작하고 validation/test의 **실제로 분석 가능한 고유 면적이 각각 20 deg² 이상**이 될 때까지 추가한다. 반경 최대 30 arcmin 자료를 사용하되 mask와 중복 면적을 빼므로 30개만으로 충족된다고 가정하지 않는다. 비용이 이 범위를 허용하지 않으면 축소 pilot 결과만 보고하고 전면 승격을 보류한다.

각 층의 면적·노출 수·시간 범위·파장 범위·mask 비율을 기록한다. 사용한 영역 목록은 결과를 본 뒤 골라 바꾸지 않는다. split과 관측 버전이 바뀌면 benchmark ID도 바뀐다.

## 4. 누출을 막는 분할

- source identity, 원 노출 파일, 중첩 하늘 footprint를 그래프로 연결한 뒤 연결 성분 단위로 split한다. 같은 원 FITS의 잘라낸 다른 영역도 다른 split에 넣지 않는다.
- 한 천체의 모든 방문, 주입 파생본, 증강본은 같은 split에 속한다. 원 노출이 겹치는 경우 영역 경계를 옮기거나 한 split으로 합친다.
- 기본 비율 60/20/20을 목표로 하되 validation/test 최소 면적을 먼저 충족한다. seed와 split manifest를 고정한다.
- 일반화 확인용 별도 future-time holdout을 둔다. 같은 하늘의 시간 holdout은 독립 영역 test와 구별해서 보고하며 수치를 합치지 않는다.
- normalization·PSF 잔차 모델·분류기·임계값은 train/validation에서만 결정한다. test 영역의 타깃 라벨로 튜닝하지 않는다.
- 배포 시에도 수행할 비교 별 기반 보정은 사전에 정한 절차로 test에서 허용한다. test 타깃을 보정 표본에서 제외하고, 이것이 학습 통계가 아닌 노출별 측정임을 기록한다.
- bootstrap 단위는 독립 영역/노출 연결 성분이다. patch 단위 bootstrap으로 신뢰구간을 좁히지 않는다.

## 5. 주입·회수 실험

주입은 **보정·배경 제거·검출·기준 영상 생성 이전의 native L2 IMAGE**에 한다. 관측 시간과 bandpass를 적분한 SED·운동·변광을 ePSF로 픽셀에 투영한다. 참조 영상에 주입 신호가 들어가는 정도와 self-subtraction도 전체 파이프라인에서 평가한다.

주입·검출 템플릿·최종 적합의 시간 적분은 설계 6절의 같은 규칙을 사용한다. midpoint 근사가 허용되는/안 되는 이동 속도·flare 지속시간을 각각 검사한다. 높은 SED 곡률과 시간-파장 상관 >0.95인 자료는 정답을 억지로 맞추는 평가가 아니라 식별 불가 상태를 올바르게 반환하는 평가에 포함한다.

주입 파라미터는 진실값 파일에 보관하고 탐지 작업에는 전달하지 않는다. 연관 허용오차는 validation에서 정해 test 전에 고정한다. 하나의 주입 천체는 여러 노출에 나타나도 회수 1건으로 센다.

| 축 | 표본 설계 |
|---|---|
| 밝기 | 단일 노출 예측 SNR 약 1–30을 로그 간격으로; threshold 전후를 조밀하게 |
| 운동 | 0 포함, 단기 0–300 arcsec/hour, 장기 0–30 arcsec/year; 경계 밖 별도 stress test |
| 시간 | 일정, 단조 증가/감소, 주기적·비주기적 변광, 단발 flare, 불규칙 관측 결측 |
| 분광 | 여러 기울기/색, 흡수·방출 특징, 높은 곡률, 비교 가능한 동일 SED의 상수 천체 |
| 공간 | subpixel 위치, 중앙/가장자리, 이웃 천체와의 분리/밝기비, 포화 근처 |
| 기기 | PSF/좌표/배경 보정 오차, 서로 다른 검출기/방향/처리 버전 |

주입 신호가 만드는 추가 잡음은 전자수·gain·적분시간의 의미를 확인한 경우에만 물리적으로 추가한다. MJy/sr 숫자에 직접 Poisson draw를 하지 않는다. 이 변환을 검증할 수 없으면 background-dominated 주입으로 범위를 제한하고 source-noise 누락을 보고한다. 포화·비선형·mask 반응까지 모사하지 않았다면 그 regime의 회수율은 보고하지 않는다.

한 영상의 주입 밀도는 자연 혼잡도를 유의하게 바꾸지 않게 제한하고, 한 번에 주입하는 천체 수와 최소 간격을 manifest에 기록한다. 단순 Gaussian PSF 주입만으로 ePSF 검출기를 평가하지 않는다. 학습 주입기와 다른 SED/PSF 오차/시간 생성기를 holdout에 사용한다.

## 6. 실제 후보 라벨과 설명 평가

카탈로그 일치 후보는 위치·시각·파장 조건을 확인한 positive control이고, 미일치 후보는 미확인 상태다. unmatched를 negative로 쓰지 않는다. 기기 아티팩트는 원영상·FLAGS·여러 시점 근거로 검토한다.

최소 두 사람이 독립 검토하는 방식이 최종 목표다. 사람 검토자를 확보하지 못하면 자동 라벨 성능으로 대체하지 않고, 주입 실험과 미검토 실제 후보를 구분한 연구용 결과로 남긴다. 검토 항목: 실제 광원 근거, 운동/변광 근거, 비교 파장 적절성, 혼잡·mask·아티팩트, 결론 보류 여부. 불일치는 adjudication 전까지 `uncertain`이다.

G2의 기본 절차는 **고정 test 영역에서 각 방법의 최종 문턱을 넘은 후보 합집합의 전수 검토**다. 검토자에게 제안 방법과 모델 점수를 가리고, 분기마다 accepted/rejected/uncertain을 기록한다. 같은 후보에 이동 accepted·변광 rejected가 공존할 수 있다. 실제 별의 존재만으로 변광 positive 라벨을 주지 않는다.

전수 검토를 끝내지 못하면 G2는 `inconclusive`다. 검토가 끝나도 uncertain은 오탐 예산 계산에서는 모두 false라고 둔 보수적 상한 `(rejected + uncertain)/usable area`를 사용한다. 이것은 운영 예산의 상한이며 uncertain을 학습 negative로 재라벨하지 않는다. 분기별 오류와 후보 전체 any-event 오류를 둘 다 보고한다. 하나의 잘못된 분기 주장이라도 사용자에게 제시되면 분기 오탐 예산에 포함한다.

확률 보정은 해당 후보 선택 과정을 거친 대표성 있는 실제 validation 표본에서 한다. 분기 확률은 최소 200개 검토 라벨과 각 class 50개 이상을 확보해야 제공한다. 표본을 균형화했다면 원 후보 모집단의 표집 가중치를 복구한다. 10개 equal-mass bin의 ECE와 신뢰구간을 함께 보고하며 부족한 분기는 null로 유지한다. any-event head는 설계 8절의 OR 사건으로 별도 보정한다.

VLM 설명의 검사는 ① 측정 인용 정확성 ② evidence ID의 실제 존재 ③ 지원하지 않는 결론 여부 ④ 불확실성 표현 ⑤ 사용자의 판독 도움을 평가한다. 자체 LLM 점수만으로 통과시키지 않는다. 실제 표본이 작으면 표본 수와 이항 신뢰구간을 함께 보고한다.

## 7. 지표 정의

| 축 | 지표와 계산 단위 |
|---|---|
| 탐색 | 주입 source/event recall, precision, false candidate episodes / usable deg² / 명시된 전체 캠페인 |
| 완전도 | flux·운동 속도·방문 수·파장·혼잡도별 recovery curve. 구간별 분모 공개 |
| 측광 | bias, robust scatter, pull `(Fhat-Ftrue)/sigma`, 68/95% interval coverage, 상한의 coverage |
| 위치/운동 | 접평면 bias·오차 타원 coverage, 운동 벡터 오차. 단기·장기·시차를 분리 |
| 확률/OOD | Brier score, reliability diagram, ECE와 bin 정의, OOD recall 및 abstention 비율 |
| 검색 | 수치 조건 위반 수, Recall@20, nDCG@10, 한글/영문 동일 의도 일치, 미지원 질의 감지 |
| 운영 | 노출·후보 수별 실행시간, peak RAM/VRAM, 다운로드 bytes, 캐시 적중, 실패/재개 복구율 |

usable area는 해당 분기가 요구하는 노출·파장·시점 수를 실제로 갖춘 구면 영역의 합집합이다. 같은 하늘을 여러 번 타일링한 면적을 더하지 않는다. false episode는 같은 아티팩트가 여러 노출/경로에서 제안되어도 연관 후 한 건이다. 단기 창을 여러 번 훑은 결과는 전체 지정 캠페인의 후보로 합쳐 센다. `per day`로 임의 환산하지 않는다.

동일 자료에서 baseline과 baseline+learned를 paired 비교하고, 영역 단위 bootstrap 2,000회로 95% CI를 산출한다. 20개 미만의 독립 평가 성분이면 CI를 확정적 근거로 쓰지 않는다. 작은 분모의 strata는 점추정과 불확실성을 그대로 표시하고 좋은 strata만 평균하지 않는다.

## 8. 사전 통과 기준

| Gate | 통과 조건 | 실패 시 행동 |
|---|---|---|
| G0 자료 계약 | 2절 계약 검사 통과, 사용한 정밀 파장/ePSF/분산의 출처 검증 | 정밀 분석 비활성화, 부족 자료 보고 |
| G1 기준선의 과학 건전성 | 상수 천체의 파장 변화만으로 변광 확증하지 않음; 고 SNR·비혼잡 주입의 중앙 측광 bias ≤5%; 위치 중앙 bias ≤0.1 pixel; 68% interval coverage 0.60–0.76 | 오차 모델·보정·적합 수정, 해당 regime 제한 |
| G2 학습 검출 승격 | validation에서 false episode 예산 ≤1/usable deg²/campaign로 선택한 문턱을 고정하고 test에서 비교. 합집합+재검증 recall이 baseline보다 ≥5 percentage points 개선, 차이 95% CI 하한 >0; 주요 strata에서 >3 points의 유의한 악화 없음 | baseline 기본 유지, 학습 출력 실험 표시 |
| G2 보충 | test에서 전수 검토가 끝나지 않았거나 보수적 false 예산을 초과하면 승격하지 않음. 분기별 예산 합계도 전체 ≤1/usable deg²/campaign 범위에서 사전 고정. G1 bias/coverage 유지. ECE ≤0.05는 6절 표본 조건을 만족한 실제 라벨에서 판단 | `probabilityReal`/해당 분기 확률 미제공 또는 연구용 표시 |
| G3 검색 | 수치 조건 fixture 위반 0건; 라벨된 질의에서 nDCG@10 ≥0.80, Recall@20 ≥0.90 목표; 지원 불가 필수 조건을 조용히 삭제하지 않음 | 조건 검색을 기본으로 유지, 문제 모드 제한 |
| G4 설명 | 근거/측정 인용 자동 검증 통과율 100%; 검토 표본에서 중대한 무근거 주장 0건 관측 + 표본 수/CI 공개 | 결정적 설명으로 fallback |

G1의 고 SNR은 주입 진실값 기준 예상 SNR ≥10, 비혼잡은 PSF footprint 내 이웃 오염 <10%로 사전 정의한다. 다른 regime은 제외를 숨기지 않고 별도 completeness와 오차를 보고한다. G1 기준을 모든 실제 자료에서 자동 충족한다고 가정하지 않는다.

G2의 false episode 예산은 모델 제안 수가 아니라 **최종 재검증 이후**의 결과에 적용한다. 분기별 배분은 validation에서 전체 예산을 넘지 않게 결정해 고정한다. 데이터가 너무 적어 기준의 차이를 판별할 수 없으면 `inconclusive`가 올바른 결과다.

## 9. 학습·비교 실험

| 실험 | 질문 |
|---|---|
| B0 | 물리 기준선만으로 어디까지 가능한가? |
| B1 | 영상 CNN만으로 기준선보다 나아지는가? |
| B2 | 시간 인코딩이 느린 이동과 변광에 기여하는가? |
| B3 | 시간+정밀 파장 metadata가 색에 의한 오탐을 줄이는가? |
| B4 | 후보 합집합 뒤 물리 재검증이 추가 회수와 오탐에 어떤 영향을 주는가? |
| B5 | 임베딩이 구조화 조건/문자 검색 위에 관련성 개선을 주는가? |
| B6 | VLM 설명이 정확성과 판독 시간을 개선하는가? |

주 모델은 설계서 7절의 구조다. 초기 학습 범위: pretrain 최대 100,000개 관측 집합, fine-tune 최대 20,000개 주입/검토 candidate sets, seed 3개, AdamW 초기 lr 3e-4·weight decay 1e-2, 최대 50 epoch, validation 목적함수 patience 8. 작은 실데이터에서는 표본 수를 부풀리지 않고 실제 개수를 사용한다. 이 설정은 시작점이고 변경은 test를 보기 전에 기록한다.

초기 예산 상한은 24 GiB급 GPU 1장 기준 총 72 GPU-hour의 탐색·학습이다. GPU 가용성은 아직 확인하지 않았다. 실제 속도를 1,000개 집합으로 측정한 뒤 batch/gradient accumulation을 조정한다. 예산에 닿으면 현재 모델과 결과를 남기고 표본 수/모델 폭을 줄이는 별도 run을 만든다. 성능 통과를 위해 무제한 학습하지 않는다.

## 10. 검색·표시 검증 세트

- 한/영 질의 최소 60쌍: 수치 비교·단위 변환·기간·영역·분기·유사 후보·미지원 요청을 포함한다.
- RA 경계/극점, `null` confidence, µJy/mJy, arcsec/hour↔arcsec/year, 결과 없는 영역과 미분석 영역을 검사한다.
- 전체 기간에서는 변광하지만 선택 기간에서는 일정한 예제, 4 µm 밖의 변화, 밝아짐/어두워짐 방향, 단기/장기 운동값 혼용, 범위 밖 fit의 `requires_refit`를 검사한다. 관련 확률은 범위에 맞는 분기 확률을 사용한다.
- 정적 브라우저 검색과 로컬 SQLite 검색의 필터 결과 ID가 동일해야 한다. 문자열 관련성 tie는 ID로 결정한다.
- 기본 warm query 예산: 지역 후보 10,000개에서 p95 <500 ms. 하드웨어·브라우저·전송 제외/포함 구간을 기록한다. 성능을 충족하지 못하면 샤드 크기를 줄이고 측정한다.
- 원영상과 근거 패널의 orientation·동일 stretch·파장/시간 표시, 빠른 모드 전환 취소, 누락 산출물·오래된 schema를 브라우저에서 확인한다.

## 11. 저장할 실험 산출물

`vision/runs/<runId>/`에 config, inputs, split, calibration, metrics, candidate/evidence manifests, 환경 lock hash, 모델 체크포인트 hash, 경고와 실제 자원 사용량을 남긴다. 대용량 관측·checkpoint·credentials는 소스 관리에 넣지 않는다.

평가 보고서는 결과 표뿐 아니라 실패 예제, 제외 사유, 지원 범위, 재실행 명령, baseline 비교, 계산 비용을 포함한다. 확정할 수 없는 항목은 `not_evaluated` 또는 `inconclusive`로 남긴다. 논문 수준 또는 전천 성능이라는 표현은 해당 범위의 독립 검증이 있기 전에는 사용하지 않는다.
