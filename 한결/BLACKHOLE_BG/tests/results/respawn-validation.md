# 병합 후 재등장 연속성 검증

## 원인

`_spawn`은 새 body만 추가하며 페이지나 GPU 자원을 재로딩하지 않는다. 하지만 새 물체의 렌즈는 화면 전체에 영향을 주므로, 화면 밖 생성이라도 즉시 전체 강도의 렌즈를 켜면 별 지도에 한 프레임 불연속이 생긴다. 이 경로를 실제 렌더러로 고정 시각·동일 장면의 생성 전후 픽셀을 비교하여 재현했다.

## 변경

- 새 객체의 광학 `arrival.opacity`를 0에서 시작하고 2초 벽시계 quintic으로 1까지 전환한다. 양 끝의 속도·가속도는 0. 반올림 오차로 1을 넘거나 감소하지 않도록 제한한다.
- 시작 위치에 충분한 바깥 여백을 더해 그림자가 화면에 들어오기 전에 전환할 수 있게 한다.
- 공유 광학 필드의 opacity를 사용하므로 그림자와 휨이 따로 나타나지 않는다. 질량·궤도 좌표·속도·기존 물체의 물리 시계/병합 횟수/파형 버퍼는 전환 때문에 바꾸지 않는다.
- 유입 중 렌더 상한60fps, 완료 후 기존 조건에 따라30fps. 4회 병합 후 퇴장 유지.
- 유입은 배경의 유한 영역 경계 연출이며 GR 질량 생성 모형이 아니다.

## 결과

- `node --test tests/`: 52/52 통과. 시뮬레이션과 파형 기록 유지, 4방향 바깥 시작 여백, 연속적·단조·유한 광학 가중치와 정확한 완료 상태 검사 포함.
- `TEST_PAGE=tests/gpu/respawn.html node tests/gpu/run.mjs continuity '[]'`: 4방향 통과. 생성 한 프레임의 차이가 수정 전 평균RGB 약3.03~3.05/255·큰 차이 픽셀 약4.5%에서 수정 후 정확히0으로 줄었다. 첫1/60초 최대 채널 차이1/255, 큰 차이 픽셀0. 고정 위치에서 전환만 검사하며 본체의 이동·질량 변경 없음. `respawn-before.json`, `respawn-after.json`.
- 기존 광학 GPU 34개 상태 모두 통과 (`respawn-optics.json`).
- 실제 연결된 Chrome에서 버튼으로 병합→재등장 경로 실행. 병합1회, 4.025초 뒤 유입1회, 생성 CPU0.4ms. 생성 전후 ±0.5초 rAF59개 중 p95 17.8ms, 최대33.4ms. 캔버스 width/height 변경0, 배경 texture/GL program 동일, buffer 동일, WebGL 오류0, 콘솔 warning/error0. `respawn-browser.json`. 이 측정은 브라우저/기기 한 번의 관측으로 모든 기기의 무끊김 보장이 아니다.
