# 두 번째 수정 검증 — 2026-11-14 KST

이 기록이 첫 번째 browser-validation.md보다 최신이다. 메인은 여전히 실시간 PN/EOB 근사이며, 이 검사는 수치상대론 공통 지평선의 정확도 보증이 아니다.

## 원인과 수정

1. 그림자는 화면의 유클리드 원, 렌즈는 구면 각거리로 계산해 화면 가장자리·큰 크기에서 경계가 달랐다. 병합에서도 그림자와 렌즈의 전환이 독립적이었다. 이제 같은 구면 광학장 S, 같은 x=S^(1/4)=1 포획/강한 휨각 경계를 사용한다. 쌍성장은 광학적 근사이고 고립 단일체는 Schwarzschild 휨각 극한을 유지한다.
2. 놓을 때 포인터 보간의 큰 속도가 초기 속도로 남았다. 가까운 상대와 co-moving한 배치 모드로 바꿨다. 물리 방정식에서 반중력을 넣거나 모든 비구속 궤도를 강제로 병합시키지 않는다.
3. 큰 객체는 상대가 있거나 병합 중이면 기존 퇴장 조건을 통과하지 못하고 계속 성장했다. 이제 크기 기준을 넘으면 추가 포획을 중단하고 약 6초 동안 전체 광학 이미지를 가장자리로 보낸다. 이 변환은 물리 recoil과 별개다.
4. t=0 파형 샘플, EOB 병합 시계의 서브스텝, cold merger 슬롯, 조용한 drain 슬롯 재사용을 수정했다. 메인 히스토리를 4096 샘플로 늘렸다. 패널은 방출 파형, 배경은 t−r/c로 구분한다.

- CSS 2035×1148, 버퍼 2306×1301 (약 300만 픽셀).

- 렌더는 평상시 30fps, 드래그·빠른 궤도·퇴장·클릭 파동 중 최대60fps. 검사에는 이 상태들이 섞여 있다. `performance-browser-round2.json`.

## 남은 범위

PN/EOB 좌표 연결·선도 복사·쌍성 광학장·3M 이후 연결은 근사다. Kerr 잔해 렌즈·반동·공통 겉보기지평선은 구현하지 않는다. 화면 퇴장은 배경 수명 관리이며 실제 중력파 반동 계산으로 설명하지 않는다. 모든 드래그/질량비/3체 초기조건이나 모든 하드웨어를 보장하는 검사는 아니다.
