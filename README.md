# SPHEREx Sky Lab · v2.3.1

한결의 블랙홀 입장 화면, 중선의 Stellarium 플라네타리움, 경보의 TrueBlink 분석 도구와 지호의 소행성 분석 프로그램을 연결한 로컬 통합 버전입니다.

세 프로그램은 한 사이트에서 연결되며 각 화면의 엔진은 별도로 유지합니다. 입장 화면에서 플라네타리움으로는 페이지 이동, 플라네타리움에서 분석 도구로는 천체 좌표를 전달하는 내장 창(iframe)을 사용합니다. 입장 링크에 초점을 두면 엔진 파일을 미리 준비하고, 이동할 때 블랙홀 렌더링을 멈춥니다. 분석창이 열려 있는 동안에는 뒤쪽 하늘의 렌더링을 멈추며, 닫으면 선택·시야를 유지한 채 재개합니다. 분석 자료를 줄이는 것과 별개로 화면 전환 시 겹치는 작업을 줄입니다.

## 실행

1. Node.js 22 이상이 설치된 PC에서 이 폴더의 **`Start-Web.cmd`**를 실행합니다.
2. 처음 실행할 때 TrueBlink의 잠금 파일에 맞는 의존성을 설치하고, 세 화면을 `dist/`에 빌드합니다.
3. 기본 주소 `http://127.0.0.1:4173/`에서 시작합니다. 이미 사용 중이면 다음 빈 포트를 자동으로 선택하고, 실제 주소를 브라우저에서 엽니다. 사용 중에는 서버 창을 열어 두세요.
4. 입장 화면의 **플라네타리움 입장**을 누르고 하늘의 원하는 곳을 클릭하거나 한 번 탭합니다. 별이 없는 영역도 클릭한 좌표로 분석 도구가 바로 열립니다. 드래그는 하늘 이동, 휠·두 손가락 제스처는 확대·축소로 유지됩니다. 전천 지도 타원 밖의 여백은 분석하지 않습니다. 이름으로 검색한 천체는 정보창의 **SPHEREx 분석**으로 정확한 천체 좌표를 열 수도 있습니다. 분석창을 닫으면 보던 하늘로 돌아갑니다.

개발용 명령은 다음과 같습니다.

```powershell
npm run setup
npm run build
npm run preview
```

기본 실행은 사용 중인 포트를 피해 자동으로 시작합니다. 포트를 직접 고정하려면 `npm run preview -- --port 4174`로 실행하세요. `--port` 또는 `PORT`로 명시한 포트는 자동으로 바꾸지 않습니다. `index.html`을 파일 탐색기에서 직접 여는 방식은 WebAssembly와 자료 조회를 지원하지 않습니다.

## 구성

| 원본 폴더 | 통합 사이트 주소 | 역할 |
| --- | --- | --- |
| `한결/BLACKHOLE_BG` | `/` | 블랙홀 애니메이션과 입장 화면 |
| `중선/v1.2.0` | `/planetarium/` | 하늘·전천 지도, 위치·시간 설정, 천체 선택 |
| `경보/trueblink` | `/analysis/` | 선택한 위치의 SPHEREx 자료 조회와 분석 |
| `지호/spherex-asteroid-analysis` | 기존 분석 화면의 소행성 탭 | 저장된 연구 결과와 로컬 Python 분석 |

하늘 보기(입체도법)와 전천 지도(몰바이데)의 화면 투영을 역변환해 클릭한 위치를 ICRF 적경·적위(도)로 전달합니다. 화면 중심이나 가장 가까운 별의 좌표로 바꾸지 않습니다. 검색한 천체의 분석은 그 천체의 정확한 좌표와 표시용 이름을 전달합니다. 천체 이름을 다시 검색해서 다른 좌표로 바꾸지 않습니다. 분석창에서 쓰는 관측 자료는 SPHEREx가 실제로 수집한 과거 영상이며, 플라네타리움의 시뮬레이션 시각과 동일한 시점의 영상이라는 뜻은 아닙니다. 하늘 클릭에 따른 영상 조회는 고정 좌표 주변을 검색합니다. 이동 경로를 따라 자료를 모으려면 소행성 탭에서 소행성 이름·번호와 관측 기간을 지정해 새 분석을 실행하세요.

처음 여는 천체는 관측 시기와 선택한 파장 묶음 안의 채널을 나눠 최대 **48개 노출**을 먼저 불러옵니다. 수백 개의 자료를 기다리는 대신 먼저 영상과 예비 측정을 볼 수 있습니다. 상태 줄에 실제 사용한 노출 수와 일부 자료라는 안내가 표시되며, **나머지 노출 불러오기**를 누르면 최대 360개씩 추가하고 측정값을 다시 계산합니다. 추가 자료가 있는 동안에는 전체 파장·시기 범위를 분석한 결과가 아닙니다. 원본의 품질 플래그와 연구 모드의 오차·배경 자료는 그대로 사용합니다. 기본 제공 대상의 저장된 묶음은 기존처럼 최대 360개를 바로 사용하고, 같은 천체를 다시 열 때는 기존 브라우저 캐시를 활용합니다.

## 소행성 분석

분석 화면에서 연구 모드의 **소행성** 탭을 열면 지호의 저장된 결과 6개를 볼 수 있습니다. 관측 스펙트럼, 반사광·열복사 분리, 분류 후보, 흡수 특징·광물 후보, 지름·반사율·질량·밀도 및 자료 출처를 기존 웹 안에서 보여줍니다. 기존 TrueBlink의 4개 대상 비교 분석과 현재 관측 영역의 태양계 천체 표시도 유지합니다.

저장된 결과는 Python 설치 없이 열립니다. `npm run build`가 `지호/spherex-asteroid-analysis/outputs/`의 OBSERVED 결과를 웹 자료로 내보냅니다. 파일별 단위와 원래 분석 결과를 유지하며, Python의 μJy 스펙트럼을 기존 mJy 분석에 다시 넣거나 자전 보정을 중복 적용하지 않습니다. 검색으로 찾은 영상 범위와 실제로 분석한 영상 범위를 구분합니다.

새 소행성 분석에는 Python 3.11 이상과 인터넷 연결이 필요합니다. 처음 한 번 **`Setup-Asteroid.cmd`** 또는 다음 명령으로 프로젝트 전용 환경을 준비합니다. 시스템 Python 패키지는 변경하지 않습니다.

```powershell
npm run setup:asteroids
```

이후 `Start-Web.cmd` 또는 `npm run preview`로 사이트를 실행하고, 소행성 탭의 새 분석에서 이름·번호, 시작일·종료일, 최대 영상 수를 입력합니다. 기존 Python 파이프라인이 별도 프로세스에서 자료 검색·다운로드·측광·모델 계산을 수행하며 웹에서 진행 상황과 결과를 확인하거나 작업을 취소할 수 있습니다. 한 번에 한 작업을 실행하고 결과는 `.asteroid-jobs/`에 별도로 저장합니다. 탭을 다시 열면 진행 중인 작업에 재연결합니다. 서버가 종료되면 실행 중인 작업은 중지됩니다.

분류 확률은 기준 스펙트럼과 모델 안에서의 상대 확률이며 실제 정답 확률이 아닙니다. 저장된 검증에서 기존 분류와 다른 사례를 표시합니다. 광물은 후보이며, 질량은 외부 카탈로그의 중력 자료를 사용합니다. `Complete`는 필요한 결과 항목이 있다는 뜻이지 높은 신뢰도를 의미하지 않습니다. 자료가 부족한 값은 추정 불가로 유지합니다.

## 자료 연결과 배포

`scripts/serve.mjs`는 정적 파일뿐 아니라 경보의 기존 `/api/sia` 검색 중계 서버와 `/hips/spherex/` 채널 처리를 함께 실행합니다. 임의의 천체 위치를 검색하려면 이 서버와 인터넷 연결이 필요합니다. 외부 서비스가 응답하지 않거나 해당 위치의 자료가 없으면 분석 도구에 오류 또는 빈 결과가 표시됩니다. 기본 제공 대상의 저장된 자료는 일부 오프라인 기능에 사용됩니다.

`npm run build` 결과는 루트의 `dist/`에 모입니다. GitHub Pages 같은 정적 호스팅에 이 폴더만 올리면 검색 중계 서버가 실행되지 않으므로 임의의 천체 조회에는 별도 중계 서버가 필요합니다. 별도 서버를 쓸 때는 `VITE_API_BASE`에 HTTPS 중계 서버의 `/api` 주소를 설정한 뒤 다시 빌드하세요. 이 버전은 로컬에 구성했으며 자동으로 GitHub에 업로드하거나 공개 배포하지 않습니다.

소행성의 저장된 결과·그래프·다운로드 파일도 정적 배포에 포함됩니다. 새 Python 분석 API는 루트 로컬 서버의 `/api/asteroid-analysis/`에서 제공하며 `VITE_API_BASE`의 외부 NASA 중계 서버로 보내지 않습니다. 현재 작업 실행은 같은 PC의 로컬 접속에 한정됩니다. GitHub Pages에서는 저장된 결과를 보고 다운로드할 수 있으며 새 계산은 로컬에서 실행해야 합니다.

```powershell
$env:VITE_API_BASE = 'https://your-relay.example/api'
npm run build
Remove-Item Env:VITE_API_BASE
```

## 수정과 확인

각 팀 폴더에서 코드를 수정한 뒤 루트에서 `npm run build`를 실행하면 통합 결과가 갱신됩니다. `npm test`는 통합 서버의 정적 경로, WASM 응답, 검색 API 연결을 외부 요청 없이 검사합니다. 분석 도구의 기존 검사는 `npm --prefix 경보/trueblink test`로 실행할 수 있습니다.

Stellarium의 소스와 AGPL-3.0 라이선스는 플라네타리움의 프로젝트 안내·소스 링크에 포함됩니다. TrueBlink의 Apache-2.0 라이선스와 고지 문서는 `dist/analysis/LICENSE`, `THIRD_PARTY_NOTICES.md`, `AI_USE.md`에 함께 포함됩니다. 각 팀의 원본 구현과 고지를 유지합니다.
